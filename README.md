# AmneziaWG каскад

Локальное веб-приложение для настройки каскадного VPN:

```
Клиент ──AmneziaWG/UDP──> Промежуточный VPS (в своей стране) :PORT_i ──DNAT──> Зарубежный AmneziaWG_i
```

Промежуточный сервер только пробрасывает UDP (iptables DNAT) и ничего не расшифровывает — шифрование сквозное между клиентом и зарубежным сервером. Один прокси может обслуживать много зарубежных серверов: каждому выделяется свой UDP-порт на прокси.

## Запуск

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8777
```

Открыть http://127.0.0.1:8777

## Как пользоваться

1. **Серверы** — добавьте все известные серверы (без ролей). После добавления сервер сканируется, только чтение: ОС, AmneziaWG (контейнер AmneziaVPN `amnezia-awg*` или нативный), существующие DNAT-пробросы (`iptables-save -t nat`, цепочка PREROUTING), занятые UDP-порты. Пробросы на адреса не из списка подсвечиваются.
2. **Каскады** — выберите прокси и один или несколько серверов выхода. Порт на прокси подбирается автоматически и никогда не пересекается с существующими пробросами и занятыми портами. Если порт указан вручную и конфликтует, будет отказ с указанием мешающего правила. На сервер выхода без AmneziaWG он будет установлен (Ubuntu/Debian, PPA `amnezia/ppa`).
   - **Существующие каскады** (проброс на прокси, сделанный не приложением, до порта AmneziaWG известного сервера) подсвечиваются жёлтым. Кнопка «Использовать» добавляет такой каскад в приложение без каких-либо изменений на прокси, после чего на него можно выдавать клиентов.
   - Приложение пишет только свои цепочки `CASCADE_PRE/CASCADE_POST/CASCADE_FWD` (скрипт `/usr/local/sbin/cascade-rules.sh` и `cascade-rules.service`), чужие правила не изменяет.
   - Состояние каскада: «применён», «правила нет на прокси» или «конфликт с чужим правилом» (красный) — по последнему скану прокси.
   - **Версия AmneziaWG на сервере выхода** выбирается при создании каскада:
     - *Как на сервере* — используется уже установленный AmneziaWG; если его нет, ставится AmneziaWG 1.0 в систему (PPA).
     - *1.0* — для роутеров (Keenetic, OpenWrt): только `Jc/Jmin/Jmax/S1/S2/H1–H4` одиночными числами. Если на сервере и так 1.0, отдельный контейнер не создаётся.
     - *2.0* — контейнер `cascade-awg-v2`: диапазоны `H1–H4`, паддинги `S3/S4`.
     - *3.x* — контейнер `cascade-awg-v3`: плюс `HeaderProtectionKey` (защита заголовков; шифр симметричный, поэтому ключ попадает и в конфиг клиента) и `ContentPaddingAddition`. Нужен клиент с поддержкой 3.x.
     Каждая версия живёт в своём контейнере (userspace `amneziawg-go`, образ `amneziavpn/amneziawg-go` закреплённой версии, своя подсеть 10.9.x.0/24 и свой порт). Ядро хоста и контейнер AmneziaVPN не затрагиваются; Docker при необходимости ставится автоматически.
   - Перед созданием каскада (и по кнопке «Проверить») приложение шлёт с прокси UDP-пробы на порт сервера выхода и обратно, считая их временным правилом в таблице `raw`. Если пакеты не доходят, каскад не создаётся: значит, трафик блокируется между сетями.
3. **Клиенты** — имя и выбор каскадов, затем «Создать конфиг». Кнопка «Обновить трафик» опрашивает серверы выхода (`awg show <iface> transfer` и `latest-handshakes`) и показывает по каждому клиенту принято/отдано и время последнего подключения. Счётчики на сервере обнуляются при перезапуске интерфейса, поэтому приложение накапливает итог у себя. Можно скачать `.conf` (AmneziaWG/AmneziaVPN) или скопировать `vpn://` ключ (AmneziaVPN). Endpoint — прокси и порт каскада.

## Требования и ограничения

- Серверы: Ubuntu/Debian, вход под root или пользователь с `sudo` без пароля.
- Учётные данные SSH и ключи клиентов хранятся локально в `data/state.json` (права 600). Лучше использовать SSH-ключи вместо паролей.
- На прокси порты UDP для каскада не должны быть заняты другими сервисами. Если у хостера есть внешний firewall — откройте эти порты.
- Удаление сервера, каскада или клиента требует ввести имя объекта в диалоге. Удаление клиента отзывает его доступ на сервере выхода.
- Удаление каскада убирает только его правило на прокси; peers клиентов на сервере выхода остаются.
- Правила, созданные только через nftables (без iptables), при сканировании не видны.

## Проверка работы

- С клиента: `curl ifconfig.me` должен показать IP зарубежного сервера.
- На прокси: `iptables -t nat -S CASCADE_PRE`, `conntrack -L -p udp`.

## Приложение АМнеЗинуVPN (`client/`, в разработке)

Кроссплатформенное приложение (macOS, Windows, Linux, Android) в стиле AmneziaVPN со своим туннелем и управлением каскадами. Ядро переписывается на Rust; эта панель остаётся эталоном: `tests/golden/gen.py` запускает Python-код и пишет эталонные ответы в `client/fixtures/`, а Rust-тесты сверяются с ними.

```bash
.venv/bin/python -m tests.golden.gen   # обновить фикстуры после изменений в app/
cd client && cargo test                # ядро и SSH-операции, сверка с Python
```

Консольная утилита `amz` работает с тем же форматом `state.json`, что и панель (серверы, каскады, клиенты, трафик):

```bash
cd client && cargo build -p amz-cli
./target/debug/amz --data ../data ls
./target/debug/amz --data ../data scan <server-id>          # только чтение
./target/debug/amz --data ../data cascade --proxy <id> --exit <id> --instance v3
./target/debug/amz --data ../data add-client phone <cascade-id>
./target/debug/amz --data ../data key <client-id>
```

Туннель на этом устройстве (пока macOS): сборка требует Go (`amneziawg-go` встраивается как библиотека), управление идёт через привилегированный helper:

```bash
cd client && cargo build --release -p amz-helper -p amz-cli
sudo ./target/release/amz-helper --allow-uid $(id -u)     # в отдельном терминале
./target/release/amz --data ../data validate              # конфиги всех клиентов принимаются amneziawg-go
./target/release/amz --data ../data up <client-id>        # или: amz up --conf file.conf
./target/release/amz status
./target/release/amz down
```

При первом подключении `amz` запоминает SSH-ключ сервера (`host_key`) и дальше отказывается подключаться, если ключ изменился.
